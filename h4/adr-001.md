# ADR 001: Fusión de Patrones Strategy y Observer

## Estado
Aceptado (Borrador para H4)

## Contexto
Sistema de Gestión de Órdenes de Trabajo necesita calcular rutas de forma dinámica según el tipo de servicio (Strategy) y notificar a múltiples interesados (Despachador, Inventario) cuando una tarea cambia de estado (Observer). 

## Decisión
Se decide fusionar los patrones **Strategy** y **Observer** en el módulo `h3/final/`.

## Alternativas Descartadas
*   **Decorator:** Se implementó en `h3/con-decorator/`. Se descartó porque mi problema principal no era apilar agregados, sino cambiar algoritmos dinámicamente y notificar eventos.
*   **Singleton:** Se descartó porque el mundo real permite múltiples instancias.

## Consecuencias
*   **Positivas:** El código es altamente extensible.
*   **Negativas:** Aumenta la complejidad inicial del código.
